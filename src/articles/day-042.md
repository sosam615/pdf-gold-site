Redacted PDFs leak information because most of them were never really redacted: a black shape was placed over the words, and the words themselves stayed in the file, along with hidden text layers, metadata and older saved versions. You prevent it by removing the content rather than covering it, saving so the page is rebuilt, and testing the saved copy before it leaves your hands.

## Quick steps
1. Open a copy of the document in Gold PDF with **Save as** (Ctrl+Shift+S), and keep the original somewhere safe.
2. Press Ctrl+F and search for every name, number and phrase you need to hide, so you find all occurrences and not just the first.
3. Press **R** and drag a box over each item, with a small margin around the text.
4. Press Ctrl+S. Each page with a redaction is rebuilt with the bars burned in, and the document title and author are cleared.
5. Close and reopen the saved file. Copy across each bar, search for the hidden words again, and check the file properties.
6. Only then send or publish the file.

## Why redacted PDFs leak information: the five usual causes
A PDF is not a picture of a page. It is a set of instructions: draw this text here in this font, place this image there, add this annotation on top. When you "black out" something, the question is whether you changed the instructions that draw the text, or simply added a new instruction that draws a rectangle over it. Most leaks come from the second case.

| Leak | What happened | How someone finds it |
|---|---|---|
| Covering shape | A black rectangle or highlight was drawn on top; the text is still underneath | Select across the bar and paste, or move the shape |
| Hidden text layer | A scan was run through text recognition, and the invisible text under the image was not removed | Search or copy on the scanned page |
| Metadata | The author, title, subject or keywords still name the person or case | Open the document properties |
| Incremental save | The file was saved by appending changes, so the earlier version is still inside | Open the file in a tool that shows saved revisions |
| Attachments and extras | Embedded files, comments, bookmarks or form field values still hold the data | Open the attachments, comments or bookmarks panel |

### 1. A shape is not a redaction
This is by far the most common cause. A black rectangle, a thick highlight, or a "whiteout" patch looks final on screen and in print, but the text is still there. Anyone can drag across the bar and copy it, and a text editor will show the words in plain form. A full explanation with a simple test is in [does drawing a black box redact a PDF](/articles/does-drawing-a-black-box-redact-a-pdf/).

### 2. The hidden text layer on scans
Scanned pages are images, but many scans also carry an invisible text layer made by text recognition, so the page can be searched. If you cover the image but leave that layer, the "redacted" words still come up in a search. The opposite mistake also happens: someone redacts the visible text layer but forgets that the scan image underneath still shows the words. A real redaction has to deal with both. The scan workflow is covered in [how to redact a scanned PDF document](/articles/how-to-redact-a-scanned-pdf-document/).

### 3. Metadata
Document properties often hold the author's name, the original file name, a case number in the title, or keywords added by a records system. None of this is visible on the page, so it is easy to miss. Check it every time, and clear anything that identifies the person or matter. Steps are in [how to remove metadata from a PDF before sharing](/articles/how-to-remove-metadata-from-a-pdf-before-sharing/).

### 4. Older versions inside the same file
Some programs save changes by adding them to the end of the file instead of rewriting it. That is fast, but the earlier version, with the unredacted text, can still be inside. A special tool can roll the file back to that earlier state. A redaction that rewrites the file avoids this.

### 5. Attachments, comments, bookmarks and form values
A PDF can carry embedded files, review comments, sticky notes, bookmark titles and filled form fields. A bookmark called "Payment to J. Smith" or a comment saying "client's home address" leaks just as well as the page text. Look in each panel before you share.

## How to prevent redaction leaks before you share
Prevention is mostly about order. Find everything first, remove it properly, then test the result as if you were the person receiving it.

**Find every occurrence.** People redact the name on page one and miss it in a footer on page twelve. Use Ctrl+F for each name, number and phrase, and also try short forms: initials, the last four digits of an account number, a nickname, an email address. Search does not see text inside pictures, so also scroll through every page by eye.

**Remove, do not cover.** Use a redaction tool that changes what is in the file. In Gold PDF, the Redact tool (**R**) marks areas, and on save each affected page is rebuilt as a sharp, high-resolution image with the bars burned in. The covered text, images and drawings underneath are replaced by solid colour, and the remaining words are restored as an invisible text layer so the page stays searchable. Pages without redactions are left as they were.

**Clean what sits outside the page.** Clear or check the title, author, subject and keywords. Delete review comments you do not need. Look at bookmarks, attachments and form fields.

**Save to a new file.** Save the redacted copy under a neutral name. A file called "smith-divorce-unredacted-v3.pdf" leaks information through its name alone.

**Test the saved file.** Do not test the copy that is still open in the editor. Close it, open the saved file, and check it with the steps below.

## How to test a redacted PDF for leaks
A quick test takes two or three minutes and catches almost every problem.

| Test | How to do it | What a safe result looks like |
|---|---|---|
| Copy test | Drag across a black bar, copy, paste into Notepad | Nothing from under the bar appears |
| Search test | Ctrl+F for each redacted name or number | No results |
| Move test | Click a bar and try to drag it | It does not move; it is part of the page |
| Zoom test | Zoom in at the edges of each bar | No letter tops, tails or digits show at the edges |
| Properties test | Open the document properties | No names, case numbers or file paths |
| Panel test | Check comments, bookmarks and attachments | Nothing sensitive is listed |

If any test fails, go back to the original copy, not the failed one, and redact again. The full check is in [how to check if a PDF redaction is secure](/articles/how-to-check-if-a-pdf-redaction-is-secure/).

> **Common mistakes**
> - Using a highlighter, rectangle or whiteout and calling it redaction.
> - Redacting the first match of a name and missing the rest.
> - Forgetting the scan image under an OCR text layer, or the text layer over a scan.
> - Leaving the person's name in the file title, author field or file name.
> - Testing the open copy instead of reopening the saved file.
> - Sending a file with review comments or attachments that repeat the hidden details.

## What Gold PDF does and does not do
Gold PDF is a free, offline PDF editor for Windows 10 and 11. ## The short version
Redaction leaks are almost never clever attacks. They are covering shapes, forgotten text layers, metadata, older versions and attachments. Remove the content with a real redaction tool, clean everything that sits outside the page, save to a new file with a neutral name, and test the saved copy before you share it.
